# 对话历史持久化设计

前期使用 PostgreSQL 三张表：`users`、`sessions`、`messages`。建表脚本为 [001_create_conversation_tables.sql](../migrations/001_create_conversation_tables.sql)，面向 PostgreSQL 14+，数据库编码使用 UTF8。

本地数据库使用根目录 [compose.yaml](../compose.yaml) 搭建，启动及连接说明见 [database.md](database.md)。Compose 使用 PostgreSQL 18，首次启动自动执行建表脚本。脚本中的 identity、JSONB、TIMESTAMPTZ 和约束均可用于 PostgreSQL 18。

## 表结构

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `users` | `id`、`username`、`nickname`、`created_at` | 保存用户身份，用户名唯一 |
| `sessions` | `id`、`user_id`、`title`、`created_at`、`updated_at` | 一个用户可以拥有多个会话 |
| `messages` | `id`、`session_id`、`role`、`content`、`reasoning_content`、`tool_calls`、`tool_call_id`、`created_at` | 一个会话包含多条消息 |

主键统一使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY` 自动生成。消息按 `id` 升序读取。接口向前端返回 ID 时使用字符串，避免 JavaScript 大整数精度损失。正文使用 `TEXT`，工具调用使用 `JSONB`。用户名唯一约束区分大小写。

用户表暂不设计登录凭证；`username` 只是身份字段，不能单凭客户端提交用户名授权访问会话。后续确定登录方式后再补充相关字段。

## 消息内容

- `role` 为 `user`、`assistant` 或 `tool`。
- `content` 保存用户输入、助手回复或工具返回值。助手只有工具调用时可以为空串。
- `reasoning_content` 可空，保存当前前端已展示的思考文本，仅供历史展示，不默认加入模型上下文。
- `tool_calls` 可空，仅 assistant 消息使用，保存调用 ID、类型、函数名和原始参数字符串组成的数组。
- `tool_call_id` 可空，仅 tool 消息填写，关联前序助手消息中的调用 ID。应用校验配对关系，避免重复保存结果。

包含工具调用的一次交互按顺序保存为 `user → assistant(tool_calls) → tool → assistant`，用于恢复模型上下文。界面可隐藏工具消息。

## 时间约定

所有时间字段使用 `TIMESTAMPTZ(6)` 保存时间点，按北京时间（中国标准时间，UTC+8）展示。脚本通过 `SET TIME ZONE 'Asia/Shanghai'` 设置当前连接；该设置不会自动影响后续应用连接。

接入数据库时，每个应用连接均需设置 `TimeZone = 'Asia/Shanghai'`；Go 侧展示和序列化也使用 `Asia/Shanghai`，接口返回带 `+08:00` 偏移的时间。PostgreSQL 在内部按 UTC 保存时间点，查询时按连接时区转换，不保存原始时区名称。

`sessions.updated_at` 不会自动随 UPDATE 改变；修改标题或新增消息时，由应用显式设置为 `CURRENT_TIMESTAMP`。新增消息和更新会话时间放在同一事务内。

## 最小读写流程

1. 服务端获取可信用户身份，创建或选择该用户的 session。
2. 校验 session 归属，读取其 messages，按 id 升序组装历史上下文，再加入本次用户输入。
3. 第一版在内存中收集本次完整的用户消息、助手消息和工具结果，模型成功结束后，在短事务中按顺序插入消息，并更新 sessions.updated_at。
4. 事务成功后发送 SSE done；失败或断开时不保存本次交互，避免将不完整的工具调用链加入下次上下文。暂不保留失败回复及中断时已显示的部分文本。
5. 会话列表按 `(updated_at DESC, id DESC)` 分页；历史消息按 session_id 查询，加载更早消息使用 `id < before_id`。

第一版同一会话请求由应用串行处理；不引入执行轮次表、心跳、请求幂等和流式快照。部署多个服务实例时需要补充分布式并发控制。工具可能在持久化前执行成功，后续如引入有副作用的工具，再增加执行记录及幂等处理。

## 接入位置

- `internal/handler/chat.go`：请求增加 session_id，首轮返回新建的会话 ID，校验归属后开始 SSE。
- `internal/service/chat.go`：读取历史、执行 Agent，并在成功结束后保存本次完整消息。
- `internal/core/agent.go`：提供完整消息结果，包括工具调用、工具返回和最终助手回复。
- repository 层：负责用户、会话、消息的 PostgreSQL 数据访问和事务。

本次只修改建表 SQL 和设计文档，未接入数据库。脚本用于首次建表；如果已执行过旧版脚本，需要另行迁移现有数据。
